## ADR-001: 采用 Next.js 16 App Router

**日期：** 2026-04-30  
**状态：** ✅ 已采纳  
**决策者：** Project Agent

### 背景
需要选择前端框架来构建律师内容平台。

### 考虑的选项
1. Next.js 16 (App Router)
2. Next.js 14 (Pages Router)
3. Create React App
4. Vite + React Router

### 决策
选择 **Next.js 16 App Router**

### 理由
- ✅ 内置 SSR/SSG 支持，利于 SEO
- ✅ App Router 提供更好的性能和开发体验
- ✅ Server Components 减少客户端 JavaScript
- ✅ 与 Vercel 部署无缝集成
- ✅ 强大的路由和布局系统
- ⚠️ 需要注意 Next.js 16 的 breaking changes

### 后果
- **正面：** 现代化的开发体验，优秀的性能
- **负面：** 学习曲线，需要适应新的 API
- **风险：** Next.js 16 文档可能不完整，需要查阅源码

## ADR-002: 使用 Supabase 作为后端

**日期：** 2026-05-01  
**状态：** 📋 计划中  
**决策者：** Project Agent

### 背景
需要选择后端解决方案来处理数据存储、认证和 API。

### 考虑的选项
1. Supabase (PostgreSQL + Auth + Storage)
2. Firebase
3. 自建 Node.js + PostgreSQL
4. AWS Amplify

### 决策
选择 **Supabase**

### 理由
- ✅ 开源，可自托管
- ✅ 基于 PostgreSQL，功能强大
- ✅ 内置认证和授权
- ✅ 实时订阅功能
- ✅ 自动生成 REST 和 GraphQL API
- ✅ 与 Next.js 集成良好
- ⚠️ 不接真实密钥，使用环境变量

### 后果
- **正面：** 快速开发，减少后端代码量
- **负面：** 依赖第三方服务
- **风险：** 需要学习 Supabase 的最佳实践

## ADR-005: 三人 Agent Team 协作模式

**日期：** 2026-05-01  
**状态：** ✅ 已采纳  
**决策者：** 用户 + Project Agent

### 背景
需要建立高效的 AI 辅助开发工作流。

### 考虑的选项
1. 单一 Agent 全能模式
2. 双 Agent 开发+审查模式
3. 三 Agent 管理+开发+审查模式

### 决策
选择 **三 Agent 模式**

### 角色分工
- **Project Agent (Opus)** - 项目管理、架构设计
- **Program Agent (Sonnet)** - 代码实现、功能开发
- **Review Agent (Opus)** - 代码审查、质量保证

### 理由
- ✅ 职责分离，各司其职
- ✅ Opus 负责高层决策，Sonnet 负责执行
- ✅ 双重 Opus 审查保证质量
- ✅ 符合软件工程最佳实践
- ✅ 可追溯的决策和审查记录

### 后果
- **正面：** 代码质量高，决策有据可查
- **负面：** 协作成本稍高
- **风险：** 需要良好的文档系统支持

## ADR-006: 禁止自动执行危险操作

**日期：** 2026-05-01  
**状态：** ✅ 已采纳  
**决策者：** 用户 + Project Agent

### 背景
需要建立安全边界，防止 AI 执行不可逆操作。

### 禁止的操作
1. ❌ 不做第二版风格蒸馏
2. ❌ 不接真实密钥
3. ❌ 不执行数据库迁移
4. ❌ 不自动 git commit
5. ❌ 不大规模重构

### 理由
- ✅ 保护代码安全
- ✅ 防止数据丢失
- ✅ 保持可控性
- ✅ 符合最小权限原则

### 自动修复边界
- ✅ **可自动修复：** lint 错误、类型错误、导入路径、构建错误
- ❌ **必须停止：** 连续失败 2 次

### 后果
- **正面：** 安全可控，用户信任度高
- **负面：** 某些操作需要人工介入
- **风险：** 无

## ADR-007: 文档驱动开发

**日期：** 2026-05-01  
**状态：** ✅ 已采纳  
**决策者：** Project Agent

### 背景
需要建立项目知识管理系统。

### 文档体系
1. **CLAUDE.md** - 开发指南和规则
2. **PROJECT_STATUS.md** - 项目状态追踪
3. **TASK_BOARD.md** - 任务看板
4. **DECISIONS.md** - 技术决策记录（本文件）

- ✅ 支持异步协作
- ✅ AI Agent 可以读取历史上下文

### 后果
- **正面：** 项目透明度高，协作效率提升
- **负面：** 需要维护文档的时间成本
- **风险：** 文档可能过时，需要定期更新
